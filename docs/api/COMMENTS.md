# B17 — Commentaires historisés

POST /api/v1/requests/{id}/comments : membre actif vérifié, demande publique visible en open/in_progress/resolved ; brouillon interdit même au propriétaire, archive en lecture seule. Corps strict {body}, 1–4000 caractères, blancs seuls refusés, motifs de secrets et caractères de contrôle interdits. Auteur, parent, état et dates viennent du serveur. Retour 201 ; aucune transition ni modification de version de la demande.

PATCH /api/v1/comments/{id} : seul l'auteur actif vérifié, mêmes conditions sur le parent, commentaire visible ; corps strict {body, lock_version}, version entière 1–2147483646. Version périmée 409 sans mutation ; succès 200, version +1 et edited_at serveur. Aucun bypass admin. Création et édition exigent session/CSRF, Idempotency-Key UUID v4 et quota 30/minute. Même intention rejouée sans duplication, charge différente 409 ; droits actuels avant rejeu, ancienne réponse après autre édition 409.

GET /api/v1/requests/{id}/comments et GET /api/v1/comments/{id} : lecture publique suivant visibilité du parent et de l'auteur du commentaire ; commentaires masqués ou auteur suspendu/non vérifié exclus avant pagination et total. Liste chronologique created_at/id, 20 par page, maximum 50 ; filtres inconnus refusés. GET /api/v1/comments/{id}/revisions : même visibilité, version décroissante. Réponses no-store. Auteur exposé par id/handle, jamais courriel. Archives restent lisibles.

body est la source textuelle, jamais du HTML de confiance. body_html est produit avec CommonMark déjà verrouillé (licence BSD-3-Clause) : HTML brut échappé, code inerte, liens HTTPS sans identifiants seulement, rel nofollow/noopener/noreferrer ; images rendues comme libellé sans requête réseau, aucune extension mentions/pièces jointes/attributs. Profondeur limitée à 20 et 100 délimiteurs par ligne. Le client utilisera ce rendu sans réinterpréter la source en HTML. Le navigateur reste à vérifier après GO_FRONTEND.

Historique métier séparé : corps source et version à chaque création/édition ; historique d'un commentaire retiré inaccessible avec lui. Au premier changement d'un commentaire B11 préexistant sans historique, une capture before_edit conserve sa version courante, datée de la capture ; elle n'invente pas ses éditions précédentes. Audit commun minimal sans corps, version et request_id seulement. Table additive comment_revisions ; aucune migration B11 réécrite.

Verrous : comptes acteur et auteur du parent triés par UUID, puis socle idempotence (acteur déjà verrouillé), demande, commentaire. Relecture des droits, visibilité, état et version sous verrou. B16 acquiert aussi le parent : une contribution rend la note d'édition obligatoire dès qu'elle est commise. Les futurs écrivains/modération doivent conserver cet ordre. Rollback commun corps/historique/audit/notification/intention.

Événement comment.created : UUID du commentaire comme événement stable, destinataire auteur du fil déterminé côté serveur, aucun auto-envoi. Intention minimale dans l'outbox existante ; livraison par notifications:deliver après commit, reprise/déduplication existantes. Une édition ne renotifie pas. Liste/compteur/marquage de notifications recontrôlent la visibilité actuelle du commentaire et du parent ; message générique et chemin interne, aucun extrait. Aucun courriel ni notification externe envoyé par ce lot.

B17 ne livre pas B18/B19 ni les projets BC04/BC05. Contrôles projet à raccorder lors de leur livraison. Contrôles Markdown fondés sur la documentation officielle : https://commonmark.thephpleague.com/2.x/security/ et le code de la version verrouillée.
